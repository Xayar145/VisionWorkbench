# 工业通信

通信与视觉流程通过 `DeviceRequest` / `DeviceReply` 对接。TCP 服务和串口服务处理请求，Modbus 主站轮询 PLC；协议层不依赖 WPF，也不直接修改视觉流程。

## TCP/IP 与串口

TCP 默认监听 `127.0.0.1:8500`，可在设备设置中绑定本机的 PLC 网络接口 IP。该服务没有身份认证，应仅在可信设备网段使用。`STATUS` 读取状态，`TRIGGER` 请求一次检测；正在采集或执行时是否允许触发，由应用统一判断。

使用 UTF-8，每行一条 JSON，以 `\n` 分隔（也兼容 CRLF）。字段名大小写不敏感。一个连接可连续请求，同一连接严格按行顺序处理和响应；不同 TCP 客户端可并行连接，视觉运行仍由统一执行入口控制。请求编号由调用方提供，响应原样带回。

```json
{"command":"STATUS","requestId":"plc-1"}
{"command":"TRIGGER","requestId":"plc-2"}
```

```json
{"requestId":"plc-1","success":true,"state":"READY","report":null,"error":null}
```

执行错误使用 `success:false`、`error` 描述原因；检测执行成功但判定 NG 时，`report.accepted` 为 `false`。不能只凭 `success` 判断工件合格。

单行上限 16 KiB，TCP 最多同时接受 8 个客户端；超长行返回失败并关闭该连接，非法 JSON 或单次业务错误返回失败后继续处理后续行。停止服务会取消监听、连接读写和正在执行的业务，并等待业务真正结束后返回；不会把拍照或检测任务遗留在后台。原生采集接口需等自身超时或返回，因此停止耗时受采集超时设置影响。

串口 `SerialInspectionChannel` 使用相同 JSON 行协议，默认 8 数据位、无校验、1 停止位，波特率可选。串口数据在工作线程读取，读取超时会周期检查取消；关闭会终止读取并释放端口。普通串口 JSON 协议与 Modbus RTU 使用不同端口会话，同一个 COM 口不能同时打开两种协议。

## Modbus TCP / RTU

协议实现复用 MIT 开源库 [NModbus](https://github.com/NModbus/NModbus) 3.0.83；RTU 串口适配使用 `NModbus.Serial`，没有手写另一套 Modbus 编解码。主站支持 FC03 保持寄存器读取及 FC16 多寄存器写入。地址使用协议的从 0 开始地址，例如面板标记 40001 常对应协议地址 0，需核对具体 PLC 地址表。

TCP 默认连接 `127.0.0.1:502`、站号 1。RTU 可设置 COM、波特率、站号、校验位、数据位、停止位。所有读写通过一个异步锁串行化。默认连接/读写超时 1500 ms，不自动重试；失败、超时、主动取消会关闭真实连接。重新连接需要显式操作，避免错误写入被隐式重发。

上层设备运行服务负责触发寄存器的 0→非 0 边沿识别、运行互斥和结果回传；寄存器映射以设备页面和 `DeviceRuntime` 为准。

## 验证范围

集成检查使用真实本机 TCP 连接验证 JSON 分帧/粘包、多个请求、无效行、业务异常隔离、长度上限、停止和重启。Modbus 检查通过 NModbus 真实主站连接本机 NModbus 从站，验证 FC03、FC16、并发串行化、断线和无响应超时。串口只验证枚举与关闭生命周期；没有将枚举成功当作物理通信成功，RS-232/RS-485 和 RTU 仍需真实设备或虚拟串口对验证。

设计参考 MIT 项目 [vision-pilot](https://github.com/agentthink/vision-pilot) 的请求隔离、PLC 轮询和握手分层；当前通信协议代码与寄存器接口独立实现，未复制其手写 Modbus 协议实现。

## 站点握手映射

默认触发保持寄存器地址为 0，结果起始地址为 10；都是从 0 开始的协议地址，可在设备页修改，不能重叠。

| 地址偏移 | 内容 |
|---|---|
| 触发地址 | PLC 写 0→非 0 发起一次新检测；保持非 0 不重复，下一次必须先回 0 |
| 结果 +0 | 完成标记：开始写 0，结束写 1 |
| 结果 +1 | 0=处理中，1=OK，2=NG，3=执行/采集错误 |
| 结果 +2 | 本次轮询会话的 ushort 周期序号 |
| 结果 +3 | 算法耗时毫秒，超出 ushort 范围截断 |

执行前清空旧完成标记，重新采图后运行真实流程并回写。轮询参数在启动时快照；修改连接参数需断开重连，修改地址/周期需停止后重新启动轮询。保存配置会显示下次连接生效说明，不代表已修改正在运行的会话。

停止检测周期时，如果 PLC 连接仍然可用，写入错误完成标记；如果已断线，不能保证寄存器被写入，PLC 端需要自己的握手等待超时。周期序号从每次启动轮询的 1 开始，不能当作跨进程永久订单号。

TCP 状态有 READY、DISCONNECTED、BUSY；执行结果有 OK、NG、ERROR。TRIGGER 必须连接相机，没有用旧图代替新拍照的降级路径。非空 requestId 在进程内共享执行中任务并缓存最近 256 个已完成结果，重发同一编号返回原运行报告；上位系统应给每个新周期分配新编号。该去重不跨应用重启。

启动 TCP 服务后，可从项目 PowerShell 调用：

```powershell
.\scripts\tcp-trigger.ps1
.\scripts\tcp-trigger.ps1 -Command TRIGGER -RequestId cycle-001
```

追溯 CSV 与通信报告保留相同请求编号和运行编号。详情见 [采集与追溯](Acquisition.md)。
